# FIRE

面向中国个人与家庭的本地 FIRE 规划工具。六步输入生活与时间、当前资产、人生节点、保障与收入和投资假设，用月度资金路径回答：需要多少资金、预计何时满足条件、希望退休前每月还需增加多少净投入。

React + TypeScript + Vite；无账号、无服务端、无云同步。个人数据默认空白，示例方案单独标识。金额默认按今天购买力显示，也可切换各时点名义金额。结果基于明示假设，不代表保证收益或保证可以退休。

## 本地运行

需要 Node.js 22.12+（或 24+）。

```sh
npm ci
npm run dev -- --host 127.0.0.1
```

打开终端显示的本地地址（默认 http://127.0.0.1:5173）。生产构建与预览：

```sh
npm run build
npm run preview -- --host 127.0.0.1
```

## GitHub Pages 发布

站点地址：<https://tchaikovsky66.github.io/FIRE/>。推送 `main` 后，`Deploy GitHub Pages` 工作流依次执行单元测试、Pages 生产构建、桌面与手机浏览器测试，再发布 `dist/`。也可在 Actions 中手动运行此工作流。

`npm run build:pages` 为静态资源配置 `/FIRE/` 前缀；本地开发和普通构建仍使用根路径。仓库 Pages 设置的发布源需为 GitHub Actions；私有仓库需账号套餐支持 Pages。发布不改变浏览器本地保存机制，原本地开发地址的方案需通过 JSON 导出并在新站点导入。

部署选择与限制见 [发布决策](docs/decisions-deployment.md)。

## 使用

1. 建立空白方案，或载入明确标识的示例体验。无收入、无某类资产请明确填 0；空白与零不同。
2. 通过六步导航修改输入。人生节点替换此后的完整预算，一次性费用单独填写。节点不会跟随希望退休年龄移动。
3. 分别填写继续购买与不再购买社保医保的养老金和医疗预算。未知待遇仅阻塞对应方案；应用不推算政策资格或疾病损失。
4. 查看两种社保方案 × 三组收益情景、目标构成、达标时间、追加净投入、月度付款不足和退休首月压力测试。
5. 方案保存在当前浏览器中。复制、比较和导入均保留现有方案；JSON 用于备份，Markdown 报告来自同一次评估快照。

收益假设包含分红利息，已扣常规成本；不单独模拟交易税费。自住房和出租房估值不进入可提款资金。债务余额仅作说明，按录入的还款现金流计支出。压力测试不自动减支、推迟退休或改变主结果。


## 实现边界

- `src/planning`：确定性的月度模型与资金反求；输入提供基准年月与全部假设，不读取时钟、网络或随机数。
- `src/session`：输入修订、最后有效结果与 Worker 生命周期。
- `src/workbench`：六步表单、可访问输入与结果图形，不自行计算金融目标。
- `src/plan-documents`、`src/local-persistence`：版本校验、导入导出和浏览器存储异常处理。
- `src/report`：从评估快照生成 Markdown；`src/display` 统一金额与时间展示。

资金目标同时满足提取率参考约束和整个退休期每月可付款约束；现金缓冲为已有资产内部划分。预计达标按候选月顺序检查，不假设人生节点使目标单调。反求金额经过正向模拟复核；超出搜索范围与数值错误独立报告。完整评估在 Web Worker 中执行，结果按输入修订接收。

本地数据依赖浏览器存储，请使用 JSON 定期备份。存储失败时保留内存方案并显示未保存；检测到损坏的旧数据时先保留原始记录，由明确的新建或导入动作重新开始保存。
