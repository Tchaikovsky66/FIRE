# FIRE 计算规格

状态：依照四轮已确认要求整理的整体方案。本文将产品规则转为可验证口径；与产品规格一起确认后实现。

实现组织与 Interface 约定见 [Module 设计](codebase-design.md)。

## 1. 单位与时间

- 按月计算，从当前规划基准月到规划终点月份，不假设只能整数年退休。
- 年龄输入转换为相对月份；收支开始时间包含，结束时间不包含。规划终点是最后一个月边界，不再扣其后的开销。
- 金额输入默认今天购买力。第 m 月物价系数 `I(m) = (1 + 通胀年率)^(m / 12)`。
- 按购买力增长的输入乘 I(m)；固定名义金额的输入不乘该系数。展示实际购买力时除以 I(m)。
- 有效年化收益转月收益：`r_month = (1 + r_year)^(1/12) - 1`。不将实际收益与名义现金流直接混算。
- 内部计算保留精度，结果展示才格式化；容许微小浮点误差，不容许用取整掩盖实际资金不足。

## 2. 每月现金流

```text
当月经常性支出 = 适用的阶段生活费
                + 未被生活费包含的社保医保、医疗自付、商业保险等
                + 当月债务还款

当月净现金流 = 当月工作净收入 + 组合外净收入
              - 当月经常性支出 - 当月一次性大额支出
```

年度生活费默认均匀分到 12 个月；事件在指定月份扣一次。用字段来源说明和分类小计防止某项同时包含在总生活费与单独付款中。

人生节点替换其后阶段预算，直到下个有效节点。退休前预算和退休后预算独立，选择候选退休年龄时按该候选时间切换适用的工作与退休状态，不移动固定婚育/养老金节点。

工资默认仅在退休前存在，退休后兼职须单独录入并设定时段。未来新增家庭成员不会自动增加收入。

## 3. 资产与现金守恒

资产拆为现金账户和各类投资账户。备用现金是现金的一部分，不是现金之外的新增资产。

月初确认已生效的预算和事件，再处理资金需求；本月收入可以支付本月支出。不足先用现金，再按所设配置从投资账户划转/变现；仍不足则记录首次资金缺口。账户不能因未支付账单而变成可继续赚收益的虚构负债。

现金只获得现金类收益，各投资账户只获得各自类别收益。普通月份在当月资金流处理后对剩余余额应用月收益。流入净结余先补所需现金，再按目标比例投入非现金资产。目标比例须有效且总和为 100%；当前持仓与目标配置分开。

在退休起点，将初始缓冲从已有资产中单独划出，剩余资金按该方案配置投入。每个退休周年月末尝试补足下一段缓冲窗口，其资金来源只能是已有现金或投资内部转移；年末同时按目标配置调整剩余投资。划转前后总额相同，不自动添加收入。首版不单独模拟交易税费，常规成本包含在收益假设中，报告注明。

现金缓冲用接下来约定月数的经常性生活费估算，不含一次性大额事件；规划终点以内不足该月数时只计算剩余月份。现金目标不足时标记缓冲不足，与总资产已无法付款分开。

债务余额作说明，还款按现金流进入，不从初始金融资产再次整笔扣减。房地产估值不进入金融资金池，租金只以净现金流出现。

## 4. 单个候选退休月份的资金目标

对每个候选退休月份 R 重新计算预算和收入：

1. 求退休起始完整 12 个月经常性收支的净缺口，已到规划终点时只覆盖剩余月份并按实际覆盖月数年化。
2. 提取率参考投资本金 `P_rate = max(0, 年化净缺口) / 初始提取率`。缺口不包含一次性大额支出；养老金只在实际生效月份抵扣。
3. 初始现金缓冲为 C，提取率约束对应总资金 `T_rate = P_rate + C`。
4. 按退休期完整月度收支，反求从 R 到规划终点每月都能付款所需总资金 `T_path`。现金 C 属于初始资金内部分配，不能再额外添加一次；最低搜索起点为 C。
5. 推荐退休总资金 `T = max(T_rate, T_path)`，其中初始缓冲 C 与可配置投资部分 `T - C` 单独展示。

反求使用同一模拟器与明确的初始现金分配、投资配置和时间规则，确认全部月份不发生付款透支。搜索结果必须再跑一次正向模拟验证。若数值搜索达到边界仍不能求出，显示无法在当前搜索范围求解，不将边界值冒充精确目标。

大额支出与较晚生效的预算会进入 T_path，不能仅用退休第一年净支出的乘数代表全部资金需求。未知养老金等关键资料缺失时，两方案对应结果应为待完善，不默认为零。

## 5. 达标时间

1. 按当前资产、工作净收入、阶段支出、投资收益和大额支出推算每个候选月 R 的可用金融资产 A(R)。
2. 为该 R 求目标 T(R)。
3. 同时检验退休前从未出现未支付的资金缺口、`A(R) >= T(R)`，并从 A(R) 正向模拟退休阶段至终点。
4. 从现在起按月扫描，返回第一个满足条件的 R。目标可能因婚育、养老金等不单调，不能对退休年龄直接假设单调二分。
5. 已经满足时显示现在；全部候选都不满足时显示“规划期内未达标”，并保留缺口或首次不足原因。

这是各组假设下的达标结果，不称为未来真实退休日期。

## 6. 希望退休时间与追加月投入

对用户选择的希望退休月 R：

- 显示该时点资产 A(R)、资金目标 T(R) 与目标差额。
- 从现在起在退休前每个月增加相同今天购买力的净投入 X，其名义金额按 I(m) 调整。
- 反求最小非负 X，使退休前不发生未支付的资金缺口，并在 R 达标且退休后全部月份可支付。
- 已满足时 X 为 0；R 为现在且存在缺口时，显示“需要立即补充的一次性资金”，不能除以零计算月投入。
- X 不属于退休后的兼职收入，且不因为婚育阶段改变而自动减少。基础可投入结余仍随阶段预算、收入和缴费变化。
- 反求失败、退休时间无效和关键资料缺失显示不同状态。不得输出负数“还需多挣”或无穷大金额。

## 7. 社保医保双方案

两个方案共享人生节点、资产与其他输入，只替换各自明确录入的社保医保缴费、养老金和医疗自付预算。

- 继续购买的在职缴费如已从到手工资扣除，只标注不重复扣减；自行缴费阶段进入支出。
- 不再购买从现在起不计未来缴费，但已有养老金可能保留，待遇由用户分别填写。
- 不能因取消缴费就自动将医疗自付设零或养老金清零。
- 未填写待遇与用户显式确认没有待遇是不同状态。
- 不根据资产收益反推医保报销或疾病发生概率，不把两方案的资金差异称为保障价值的完整定价。

## 8. 情景与压力测试

保守/基准/乐观是明示的收益假设集合；分别计算目标、达标时间和追加月投入，不套用概率标签。

压力测试固定同一个退休起点和初始资金，退休首月在付款和常规收益前：

- 股票账户一次乘以 0.65，债券账户一次乘以 0.95；幅度可修改。
- 现金不受冲击，仍按现金收益规则处理。
- 当月受冲击的股票、债券不再重复获得普通月收益，随后恢复基准假设。
- 保留原生活费、节点、大额支出和收入，不自动削减弹性支出。
- 展示同样起点下的最低总余额、首次付款不足月份、该月份未覆盖金额。资金不足后不通过虚构负余额继续投资。
- 主退休目标按基础模型，压力测试单独显示；失败不自动把主结果年龄改掉。

## 9. 必须验证的案例

| 情况 | 应验证的结果 |
| --- | --- |
| 无收益、无通胀、固定开销、无外部收入 | 全程资金需求可与逐月支出总和核对，缓冲不被重复加入 |
| 退休后若干年才开始领养老金 | 起领之前的缺口不能被提前抵扣 |
| 单身→结婚→生育 | 完整预算逐段替换，不累计成三个家庭预算之和 |
| 移动希望退休年龄 | 固定婚育节点不随之移动，工作收入停止时间变化 |
| 婚礼事件与阶段生活费 | 一次性金额只扣一次 |
| 组合含股票分红 | 总回报之外不再添加同一分红收入 |
| 现金补足和投资再分配 | 内部划转前后资产守恒 |
| 购买/不购买社保医保 | 未来缴费变化，已有养老金不被自动删除；已扣工资缴费不重复扣 |
| 当前已经达标 | 预计达标时间为现在，追加月投入为零 |
| 退休月为现在但有资金缺口 | 显示一次性缺口，不出现除零 |
| 某个月资金短缺而后来有收入 | 记录中途不可支付，不只看终点余额 |
| 退休第一年低支出但随后大幅增加 | 全程约束可以高于提取率参考目标 |
| 反求追加投入 | 将所得金额代回正向模拟，满足退休前后所有约束 |
| 股票零配置、压力冲击 | 股票冲击不能改变其他资产金额 |
| 输入空白、0、负数、超大值、收益接近 -100% | 区分合法零值、未填写、无效和计算范围边界 |

## 10. 精度和性能

界面显示“约”并提供年月和适当金额精度，不暗示长期预测精确到元。联动计算可使用缓存或后台计算，但所有结果必须标明属于当前输入还是最后有效输入，避免滑块已变而结果标签没有更新。

计算模块与界面隔离，使用可重复的输入输出进行测试。核心数值搜索必须有限次迭代、有停止条件，并处理不可求解和非有限数值。
